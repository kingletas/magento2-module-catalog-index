# Changelog

All notable changes to this module are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Fixed

- The install section added `repo.magento.com` beside the package feed, which stops `composer require` with a 401 on a Mage-OS store that has no keys for it. It now adds only the feed, beside the repository the store already uses, with one `composer config` command instead of a hand-edited block.
- The install section says `-W` can't move a Foundation the store pins to an exact version.

## 1.0.0 - 2026-09-23

### Added

- First release. Builds four families of document in OpenSearch: product and category per store view, price and stock per website. Product documents carry every attribute value, the product's URL, gallery, tier prices, review summary and category positions; a configurable's document also carries its super attribute rows, with their store labels, and its option rows. Price documents carry every customer group's indexed prices. Stock documents carry salable quantity after open reservations and whether each variant can be bought. Magento builds and caches configurable variants itself; they are not built from documents.
- Category lists, search lists, related, up-sell and cross-sell blocks, the CMS product list widget and GraphQL `products` fill their products' attributes from documents in one request instead of loading them from MySQL. Product pages for simple, virtual and configurable products without custom options, and category pages, load from documents too. Each has its own switch, and every switch is off on install.
- No around plugin. A listing takes the attributes documents can supply out of its database load and fills them afterwards; a product or category page's own entity reads its values through Magento's entity manager read handlers, so its entity row, its repository cache and every other plugin behave as they always do. Entries added to Magento's `AttributePool`, `ExtensionPool` and GraphQL collection-processor lists live in `etc/di.xml`, because an area file replaces such a list rather than adding to it, and a wiring test refuses an array argument on another module's class in any area file.
- Category menus, breadcrumbs and layered navigation fill each category's attributes, URL and product count from documents, on both the EAV and the flat category resource. A category document's product count equals what `Category::getProductCount()` returns. Categories already read in a request are not read again.
- A configurable's option rows, the query Magento runs once per swatch attribute per product, come from its document behind their own switch, matching Magento's rows field for field and in order. Leave that switch off where a website uses a stock other than the default one and hides out of stock products, because Magento Inventory filters those rows by salability there.
- A configurable's super attribute rows and store labels come from its document behind a switch of their own, as a real attribute collection built when Magento asks for one. A document that can't supply every row supplies none.
- A configurable's attributes are filed under its entity id and its options under the link field, so under content staging, where row ids and entity ids drift apart, one product never renders another's swatches.
- A listing reads each product's categories from its document instead of asking the database per product. Media gallery values keep the string shape the database gives them.
- Works beside `kingletas/module-catalog-batch`, which answers the same `getConfigurableAttributes()` call. This module's plugin is sorted first (`sortOrder` 10 against 20), so a configurable with a document is answered from it and the batch module answers the rest. `status` shows a `configurable_attributes` row, with `preempted` for a configurable whose document went unused because the other plugin answered first.
- Documents stay current through change-log triggers on every table they're built from, including `catalog_product_super_attribute` and `catalog_product_super_attribute_label`; a priority queue for price and stock; a refresh queue for products and categories; observers on orders, refunds, cancellations, saves and attribute saves; a per-minute sweep of new inventory reservations; and a per-minute scan for dated values and staged versions coming due. Queue topics name no connection, so they run on RabbitMQ where it is the store's default and on the database queue otherwise. Update Mode chooses between queueing, applying small batches inline, and leaving saves to the change log.
- Every request to OpenSearch goes through Magento's own client from `Magento_OpenSearch`, built from the catalog search connection or the module's own fields, with a short timeout for page reads. Writes use external versions, so an older build never replaces a newer document.
- A full rebuild writes into a new index, replays the change log from when it started, moves the alias in one request and replays anything that arrived in between. Only cache tags for changes a shopper can see are purged, through the event Magento's own indexers use. Purges run one at a time under a lock every server shares; a purge that can't get the lock within five seconds parks its tags, and the next lock holder or a job every minute purges them.
- A page falls back to the database when a document is missing, when OpenSearch fails, or while the circuit breaker is open after repeated failures. Each fallback is counted per page and reason, and `status` reports the counts against a budget. An hourly check rebuilds a sample of product documents in memory and rebuilds any that differ.
- Every document records the schema it was written in, and a page reads only documents in the current one; see *Upgrading* in the README.
- Settings in `pages/`, `features/` and `breaker/` groups, with a data patch that moves any value saved under the earlier `read/` paths.
- `kingletas:catalog-index:status`, `rebuild`, `verify` and `inspect`, four indexers, two tables (`kingletas_catalog_index_state` and `kingletas_catalog_index_schedule`) and the `kingletas_catalog_index` configuration section. Every console line, status label and exception message goes through `__()`; log messages stay in English.
- The public PHP surface is the interfaces under `Api/`, each marked `@api`. Every type they accept or return is an interface under `Api/Data` or one of the two enums there, `IndexFamily` and `PageType`, each preferred in `di.xml` to the class that implements it. A field provider is written against `DocumentDraftInterface` and `BuildContextInterface`.
- Measured in production mode. On Adobe Commerce 2.4.8-p2 with 2,048 sample products, a category page goes from 169 database statements and 48.3 ms of database time to 124 statements and 33.5 ms; with the category and swatch switches on as well, a category list of configurables makes 25% fewer queries and its median page time falls from 264 ms to 226 ms. On Open Source 2.4.8-p2 with 1,200 products, a category page makes 19% fewer queries. Eleven storefront pages and two GraphQL queries render identically with the switches off and on, once request-varying values and the orderings Magento itself doesn't stabilise are set aside.
- `docs/from-nothing.md`, a walkthrough from install to a category page served from documents.
- Requires PHP 8.4, so Magento Open Source or Adobe Commerce 2.4.8 or later, and `kingletas/module-foundation` 2.2 or later.
